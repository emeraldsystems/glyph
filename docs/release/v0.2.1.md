# Glyph v0.2.1

This patch fixes GLYPH-91: functions with the same name in separate modules
no longer collide merely because both modules are reachable during a build.
For example, a local `helper` and a `helper` reached through a transitive
import now resolve in their own modules; the issue's reproducer builds and
returns `3`.

## What changed

- Colliding functions retain their defining module's identity through calls,
  import aliases, function values, methods, and closures.
- Library entry import paths refer to one compiled module body, including
  custom entry filenames.
- Local functions consistently shadow imported functions, including standard
  library intrinsics.
- External C names remain unchanged. Compatible declarations are shared;
  conflicting declarations and executable entry-point conflicts are diagnosed.
- Unique function names retain their existing exported symbols. Struct and
  enum name collisions remain a compiler limitation.

The LLVM O2 release optimization introduced in v0.2.0 is preserved.

## Validation

- `cargo test --offline --locked`: 969 passed, zero failed or ignored.
- Release example matrix: 21 passed, one documented non-goal skipped,
  zero failures. The skipped live sequencer requires GlyphAudio and audio
  hardware; the sequencer language and WAV-rendering contracts pass.
- The original GLYPH-91 project builds and its executable returns `3`.

The run is recorded in the [release validation matrix](validation-matrix.md).

## Installing from the release tag

```sh
git checkout v0.2.1
just build && just install
glyph --version
```

A clean tagged checkout reports `glyph 0.2.1 (v0.2.1)`.
